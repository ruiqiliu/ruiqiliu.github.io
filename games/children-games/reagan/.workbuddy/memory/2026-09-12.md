## 霓虹打砖块（Neon Breaker）

- 场景：用户选择「网站开发」场景，需求为「生成一个静态网页小游戏，可直接在浏览器玩」。
- 产出：`neon-breaker/index.html`，单文件、零依赖、零资源，双击即玩。
- 技术要点：
  - Canvas 逻辑分辨率 800×620，DPR 缩放保证清晰；CSS `width:min(100%,840px,calc((100dvh-200px)*800/620))` 做自适应不溢出。
  - 背景（渐变 + 网格 + 暗角 + 顶部辉光）预渲染到离屏 canvas，每帧只 drawImage，避免重复绘制开销。
  - 球用「单位方向向量 + 统一速率」建模，减速道具只改速率不改方向；`normalizeDir` 强制 `|dy|>=0.24` 防止水平卡死。
  - 碰撞：circle-vs-AABB 返回法线与穿透深度；每帧按速度做子步进（steps = dist/6）防高速穿透。
  - 砖块按 y 升序存储，碰撞遍历中可 `break` 提前退出。
  - 音效全部用 WebAudio 振荡器实时合成，无音频文件。
  - 玩法：连击（每 4 连击 +1 倍率，上限 ×8）、5 种掉落道具（多球/加宽/激光/减速/加命）、6 种程序化关卡图案循环、hp 随关卡提升、最高分存 localStorage。
- 验证方式：无头 Chrome 截图（菜单态 + 注入 `startLevel(3);launch()` 的运行态），确认渲染、碰撞、计分、道具掉落均正常。
- 约定：中文界面，深色霓虹游戏区 + 浅色页面外壳（符合 light 主题）。

- 验证方式：无头 Chrome 注入「快进驱动」——在闭包内 `for(i<N){active.update(1/60);FX.update(1/60)}` 模拟数十秒游戏进程后截图，可在无人工操作下验证碰撞/计分/消行/生长等逻辑；配合 `window.onerror` 写入 title 做错误探测。这套方法很有效，适合以后验证任何 canvas 游戏。

## 工作目录归档到 git（机器级布局，重要）

- **关键约束：git 不跟随目录软链接。** 若仓库内 `workbuddy` 是软链，`git add` 只记录一条 mode `120000` 的软链条目，**文件内容不会进版本库**。所以「两边同一目录 + 内容可归档」只有一种布局：**真身放在仓库里，链接放在另一头**。
- 最终布局：
  - 真实目录：`~/Documents/CommonToolsTotorial/workbuddy/`（git 工作树内）
  - 软链接：`~/WorkBuddy -> /Users/ritchie/Documents/CommonToolsTotorial/workbuddy`
  - 结果：WorkBuddy 新建的会话目录会自动落到仓库里，天然可归档；`~/WorkBuddy/2026-09-12-12-33-02/...` 原路径照常可用。
- 验证过的点：`git ls-files -s` 显示 mode `100644`（真实文件而非软链）；`git cat-file -s` blob 大小 = 78744 与源文件一致；两边 inode 相同；透过 `~/WorkBuddy` 写入的新文件立即在仓库路径可见。
- 踩坑备注：
  - macOS 的 `find ~/WorkBuddy` **不会跟随起始路径的软链**（返回空），要用 `find -H ~/WorkBuddy` 或带尾斜杠。

## arcade 重构为多文件三层架构 + 新增两个游戏

- 需求（Ritchie 原话）：「新增两个小游戏 flappy bird 和 迷宫，添加到原游戏目录，并重构原静态 html，可以把 js css 和 html 分开，并把 UI/control 逻辑分离，方便 human read」。
- 结果：`arcade/` 从 78KB 单文件拆成 **36 个源文件**（4508 行 js）+ 4 个 css，共 **6 个游戏**（breaker / snake / tetris / moto / flappy / maze）。
- 目录约定（新增游戏只需动两处）：
  - `css/{tokens,base,home,play}.css` 四层，`tokens.css` 是唯一换主题入口。
  - `js/core/` 与游戏无关的基础设施：`util`（纯数学/颜色/几何，无 DOM）、`surface`（DPR + 逻辑坐标）、`input`（键盘/pointer/触屏 → 语义动作路由）、`audio`（WebAudio 实时合成）、`fx`（粒子/飘字）、`storage`、`loop`。
  - `js/ui/{home,play}.js` 只做 DOM 界面；`js/shell.js` 管首页↔游戏页与每帧驱动；`js/main.js` 负责装配。
  - `js/games/<id>/{game,view,controls}.js` 三件套；**`js/games/registry.js` 的 `games` 数组是新游戏唯一注册点**，首页卡片与数字快捷键自动跟着变。
- **三层分层的边界（本次立的规矩）**：`game.js` = 状态 `S` + `update(dt)` + 对外接口，**不碰 canvas/DOM**；`view.js` = 只读 `S` 画出来 + 给 HUD 文案，**不改 `S`、不读输入**；`controls.js` = 把输入翻译成语义动作，**不含规则**。逻辑层可调注入的 `Snd`/`FX`（等价于「事件通知」），这样 view 不必知道「刚刚发生了什么」。
- 外壳与游戏的契约固定为一份 api：`{W,H,pads,hint,cursor, start/resize/restart/destroy, update/render/hud, action(name,down), controls:{keys, pointer(game,p,type,e)}}`，`create(env)` 收到 `env={ctx,cv,Snd,FX}`。
- 搬砖搬出来的两个真 bug：
  1. `moto/view.js` 的 `segAt()/project()/drawRoad()` 引用了**没导入的版面表 `L`**（`L` 在 `game.js` 导出、view 层没有）→ 自检直接 `ReferenceError: L is not defined`；修法是给这几个函数加 `L` 参数、由 `draw(ctx,S,L)` 传进来。**教训：分层后 view 不再靠闭包拿 `L`，凡是 view 要用的版面数值都得显式传参。**
  2. 俄罗斯方块「消行」分支一直没被踩到 —— 原因是「笨玩家」总把方块堆在有洞的顶行。改用「随机挪列 ±6 + 随机旋转 0~3 次」才踩到。
- 交付物与预览限制（**沿用并验证了上午那条结论**）：`index.html` 用 ES module，**双击打不开**（CORS），必须本地服务器；真正能双击玩的是打包产物 **`dist/arcade.html`（自包含单文件，30 个 js 模块 + 4 个 css，约 141KB）**。这正是为了绕开 WorkBuddy 预览只服务单个文件、兄弟文件 404 的限制。
- `tools/build.mjs`：自己写的迷你打包器 —— 把 ES module 逐行改写成工厂函数 + 自建 `__req` 模块系统（`import {a} from './x.js'` → `const {a}=__req('路径')`；`export` 去掉、末尾 `Object.assign(exports,{...})`），再把 `<link>` 内联成 `<style>`、`<script type=module>` 内联进 IIFE，最后合成单文件。**注意：注释里别写 `css/*.css` 这种字面量，`*` 会被当非法 token 报 `SyntaxError`（踩过）。**
- `tools/selftest.mjs`：无头 Chrome 快进自检（`--headless=new --virtual-time-budget=30000 --dump-dom`），每个游戏打几千帧并模拟按键，`window.onerror` + `unhandledrejection` 收集异常，输出「HUD 快照 + 各指标峰值」，还覆盖 restart / resize / goHome 再进入。`--shots` 可顺带截图。
  - **峰值记录很重要**：只看快照会因为随后的重开而漏掉「消行」这类低频分支，所以要逐帧跟踪每个 HUD 指标的历史最大值。
  - `logic` 帧只调 `update`（不画）用于把状态快速推到很后面；第二段改用 `plan.press(i+100000, g)` 以便按阶段切换打法。
- **驱动伪随机的坑（本次最关键的一条经验）**：用 `(i*1103515245+12345)>>>17 & 3` 这种「帧号 × 线性同余」取方向，在 `i ≡ 0 (mod 8)` 的抽样点上会退化成固定 4 循环 → 蛇一直绕 2×2 小方块、迷宫走不到出口。改成按帧号哈希散列（xorshift：`Math.imul` 后 `^=>>>15/13/16`）才真随机。
- **「假玩家」打法决定分支覆盖**：flappy 原本每 17 帧扇一次翅膀，小鸟顶到天花板贴着顶管走，20 秒只过 2 根；实测扫频后改成**每 36 帧一次**（重力 1450 / 拍翅 -430 推出来的悬停节奏），连过 27 根，得分分支才算真被验证。**结论：自检里的 AI 打法要按物理参数推一推，别随手拍一个周期。**
- **自检可复现**：驱动里把 `Math.random` 换成固定种子的序列（游戏管口高度、方块序列都靠它），于是连跑两次输出逐字节一致。改动源码后若结果没变，先检查随机数是否接上。
- 最终验证：6 个游戏全 OK、`ERRORS: none`、约 19s。峰值示例——breaker 得分≤360/关卡≤2、snake 得分≤8、tetris 消行≤1、moto 得分≤1800、flappy 最好≤27、maze 关卡≤4。
- 另外用 `python3 -m http.server` + 无头 Chrome 验证过**多文件模块版**也能全部加载（跨源 import 正常），确认源码版可直接开发调试。
