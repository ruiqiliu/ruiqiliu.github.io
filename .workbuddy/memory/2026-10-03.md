## arcade：卡通形象换成五张真实儿童头像

范围 `games/children-games/reagan/arcade/`，六个游戏（打砖块 / 贪吃蛇 / 俄罗斯方块 /
暴力摩托 / 小鸟飞飞 / 迷宫探险）里所有手绘卡通与 emoji 角色，全部替换成 Ritchie 提供的
5 张小朋友照片头像。

**素材链路（可复用）**

- `tools/face-detect.swift`：macOS Vision 检出人脸框（归一化、原点左下）。手估人脸坐标
  极不准，脸偏一点就裁到下巴/背景，实际第一版就是这么翻车的。
- `tools/gen-avatars.py`：调 Vision → 按框裁正方形 → 192px JPEG（q88）→
  写 `assets/avatars/avatar-N.jpg` + 重新生成 `js/core/avatar-data.js`（base64内联）。
  `SCALE` / `OFFSET` 控制取景 tightness，戴帽子的照片要把 SCALE 调小。
- 为什么 base64 内联：`dist/arcade.html` 的约定是「双击就能玩」的自包含单文件，
  不能依赖旁边的图片；file:// 下外链图片也会被拦。内联后源码版与打包版渲染完全一致
  （已用同一份 screenshot 逐字节比对确认）。

**分配规则（关键设计）**

- 第 i 个游戏用第 `i % 5` 张，序号取 `js/games/registry.js` 里的位置。
- 于是**首页卡片 = 顶栏 = 游戏内角色 = 同一张脸**（`shell.open()` 里 `avatar.setHero(slot)`，
  三处共用 `avatar.heroIndex()`）。小朋友靠脸认人。
- 最初用「key 散列」分配，结果 6 游戏 / 5 张脸在首页撞了两张一样的脸 —— 纯散列不可用，
  必须按序号轮转。
- 主角之外的位置（摩托对手）继续散列，并主动避开主角那张脸（`avatar.index()` 里 +1 兜底）。

**踩到的坑**

1. 摩托骑手头盔上那道彩色装饰条 `rr(...)` 是按**圆**的半径设计的，叠到头像（不规则形状）
   上会横穿脸中央。换成头像后必须删掉该装饰条，只留白色描边勾轮廓。
2. `tools/selftest.mjs` 在受限 shell 里跑会因Chrome sandbox 初始化失败直接 FATAL，
   已给 BASE 参数加 `--no-sandbox --disable-dev-shm-usage`。
3. build.mjs 的模块改写只认单行 `import`；`avatar.js` 里的多行注释和
   `export const avatar = {...}` 都在安全范围内，但新增模块要沿用它的书写风格。

自检：六游戏全部 OK，`ERRORS: none`，HUD 峰值与改动前逐项一致（逻辑层未受影响）。
